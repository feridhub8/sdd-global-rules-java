# Git

## Approval steps

Every commit and push goes through three separate approvals, in this order:

1. Ask whether to commit, and show the files that will be committed.
2. After I approve, propose the exact commit message and wait for my approval.
3. After the commit, ask whether to push. Push only after I approve.

An approval covers only that one commit or push.

If I say "commit and push" (in any form), step 2 still applies: propose the message and wait for my approval. After committing, push right away without asking again (step 3 is already approved).

## Rules

- Every repo is a git repo from the start (`git init` before `openspec init`).
- Each repo has its own GitHub repository. In multi-repo projects, every repo name starts with `<project>-` (for example `xbank-specs`, `xbank-ms-account`).
- Commit after each logical step. Do not mix unrelated changes in one commit.
- Use Conventional Commits:
  - `feat:` new functionality
  - `fix:` bug fix
  - `chore:` setup, configuration, tooling
  - `docs:` documentation and specs
  - `refactor:`, `test:` as usual
- Commit the AI tool files generated by `openspec init`; they are part of the project.
- Never commit secrets (`.env`, keys, credentials). Add them to `.gitignore`.
- `.env.example` is committed and lists the keys only, with every value empty (`KEY=`). No placeholders, defaults, or sample values.
- `graphify-out/` is always in `.gitignore`.
- Every repo has a complete `.gitignore` in its first commit: OS files, IDE and editor files, build output (`build/`, `.gradle/`), secrets and local config, logs, and tool output.
